# 0008 · 재고는 숫자 한 칸이 아니라 원장 + 로트

- **상태**: 채택
- **날짜**: 2026-11-07

## 맥락

v0는 `ingredients.current_stock` 한 칸뿐이고 그 값을 바꾸는 흐름이 없었다 — 발주 권장("예측 − 재고")이 매일 같은 재고로 계산된다. 유통기한도 식자재마다 한 칸이라 화요일 · 금요일에 들어온 우유를 구분할 수 없다. 폐기는 하루 총량(kg) 하나라 무엇을 버렸는지 모른다.

재고 흐름 후보: A. 마감 때 레시피로 자동 차감 + 입고 입력 / B. 마감 때 남은 재고를 직접 적기(실사) / C. 수동으로만 고치기.

## 결정

- **원장**: 재고가 움직일 때마다(입고 · 마감 차감 · 폐기 · 실사 조정) 한 줄씩 쌓는다. 추가만 하고, 틀리면 반대 줄 → A와 B를 같이 쓴다: 평소엔 자동 차감, 가끔 실사로 맞추면 차이가 조정 줄로 남는다
- **로트**: 입고 단위로 유통기한 · 입고 단가를 가진다. 차감은 유통기한 빠른 것부터(FEFO)
- **폐기**: 원인(유통기한 만료 · 조리 실수 · 손질 · 당일 남은 수량)과 대상(재료 / 메뉴)을 기록한다
- 우선순위: 원장 · 로트 · 폐기 원인 · 실사는 M, 반제품 레시피 · 구매 단위 변환은 S, 발주서 · 생산 계획은 L
- 규칙은 [DATA_MODEL 4절](../DATA_MODEL.md#4-마감--재고-규칙)

## 검토한 대안

- **C (수동으로만)** — 제일 단순하지만 발주 계산의 의미가 사라진다
- **A만** — 시식 · 깨진 달걀 · 손질 손실만큼 이론 재고가 계속 어긋나 발주 권장이 틀린다
- **B만** — 매일 전 재료를 세야 해서 입력 부담이 크다

## 감수할 것

- 매번 원장 합계를 내면 느리다 → 로트에 "남은 양"을 같이 두고 같은 트랜잭션에서 맞추며, 둘이 같다는 것을 테스트로 지킨다
- 같은 로트를 동시에 차감할 때 락이 필요하다 — M3 딥 태스크
