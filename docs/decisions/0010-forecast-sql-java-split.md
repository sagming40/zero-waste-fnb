# 0010 · 예측은 SQL이 특징을 뽑고 Java가 보정한다, 비교는 백테스트에서

- **상태**: 채택
- **날짜**: 2026-11-07

## 맥락

딥 태스크 7의 처음 안은 "가중 이동 평균(WMA)을 Java로 한 번, SQL 윈도 함수로 한 번 짜서 비교"였다. 날씨 · 공휴일 · 콜드스타트가 섞이면 SQL 쪽이 버티지 못해 비교 범위가 WMA로 쪼그라든다.

## 결정

- **SQL(윈도 함수) = 과거 데이터에서 특징 뽑기**: 메뉴 × 날짜마다 요일 가중 WMA, 기준선(`LAG(1)` 어제 · `LAG(7)` 지난주 같은 요일), 최근 변동폭, 품절일 표시. 휴무일은 `business_day`로 거른다
- **Java = 보정**: 날씨 · 공휴일 배율, 콜드스타트(같은 분류 평균), 생산 · 발주 권장
- 둘 사이는 "특징 한 줄" 레코드 하나로 주고받는다
- **비교는 백테스트에서**: 지난 180일 × 메뉴의 "그날 기준 예측"을 Java 반복(날마다 쿼리 → N+1 모양)과 SQL 윈도 함수 한 번으로 돌려 실행 시간 · 쿼리 횟수를 잰다
- (선택) `regr_slope` · `corr`로 메뉴별 기온 민감도를 SQL로 추정해 보정 배율의 근거로

## 검토한 대안

- **전부 Java** — 읽기 쉽지만 백테스트가 날마다 쿼리를 날린다
- **전부 SQL** — 조건이 붙는 보정이 SQL에서 읽기 어려워진다
- **처음 안(같은 WMA를 두 언어로)** — 비교용 장난감에 그친다

## 감수할 것

- 계산이 두 언어에 나뉜다 → 경계 레코드를 고정하고 SQL · Java 테스트를 따로 둔다
- 데모 데이터라 백테스트는 파이프라인 검증까지다([REQUIREMENTS 4절](../REQUIREMENTS.md#4-데모-데이터와-한계))
