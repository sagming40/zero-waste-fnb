# 0006 · 인증은 Spring Security 세션 쿠키 + CSRF, 세션은 PostgreSQL

- **상태**: 채택
- **날짜**: 2026-11-07

## 맥락

브라우저 하나에서 쓰는 웹 앱이다(모바일 앱은 하지 않을 것). 여러 매장 · 역할이 있고, **직원을 내보내면 바로 막혀야** 한다. 나중에 데스크톱 · 모바일로 넓힐 가능성은 있다.

## 결정

- **Spring Security, 세션 쿠키 + CSRF**. CSRF 토큰은 쿠키로 내려 주고 헤더로 받는다
- 세션 저장은 **Spring Session JDBC**(PostgreSQL) — 재시작해도 로그인 유지, Valkey를 따로 띄우지 않는다
- **확장 대비**: 업무 코드는 "지금 사용자 · 매장"을 한 곳에서만 꺼내 인증 방식을 모르게 한다. 모바일이 생기면 `/api/mobile/**`에 토큰 필터 체인을 하나 더 둔다(Spring Security는 체인을 여럿 둘 수 있다)

## 검토한 대안

- **JWT** — 장점은 "서버가 명단 없이 출입증을 확인"인데, 서비스가 여럿으로 쪼개져 각자 확인할 때 빛난다. 서버 하나 · DB 하나라 쓸 데가 없다. 브라우저에서는 저장 위치가 골치(`localStorage`는 XSS에 털리고, 쿠키에 두면 CSRF를 다시 막아야 한다)이고, 만료 전 강제 로그아웃을 하려면 결국 명단이 필요하다. refresh rotation까지 구현하면 M2가 무거워진다
- **"모바일로 갈 거면 JWT"** — 오해다. 데스크톱(Electron · Tauri)은 쿠키가 그대로 되고, 모바일도 무작위 토큰 + 서버 명단이면 된다

## 감수할 것

- 요청마다 세션 테이블을 읽는다 — 이 규모에서는 문제없다
