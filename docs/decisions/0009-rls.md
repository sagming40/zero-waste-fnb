# 0009 · 매장 격리는 세 겹: 앱 필터 + 복합 외래 키 + RLS

- **상태**: 채택
- **날짜**: 2026-11-07

## 맥락

여러 매장이 한 DB를 쓴다. v0는 `userId = 1` 고정이라 막는 장치가 없었다. 앱의 `WHERE store_id = ?`는 한 번만 빼먹어도 남의 매장이 보인다.

## 결정

1. 앱이 "지금 매장"으로 거른다
2. 모든 매장 데이터에 `store_id`를 두고 `(store_id, id)` **복합 외래 키**로 참조한다 — 남의 매장 메뉴 · 재료 참조를 DB가 거부한다
3. **PostgreSQL RLS** — 트랜잭션마다 `SET LOCAL app.store_id`, 값이 없으면 0건, `WITH CHECK`로 쓰기도 막기, Flyway(소유자) · 앱 역할 분리 + `FORCE`, 배치는 매장마다

함정과 규칙 전부는 [DATA_MODEL 3절](../DATA_MODEL.md#3-매장-격리-rls). 딥 태스크 🧩6.

## 검토한 대안

- **앱 필터만** — 제일 단순하다. 빼먹은 쿼리 하나가 바로 유출이다
- **매장마다 스키마 · DB 분리** — 격리는 확실하지만 마이그레이션 · 배치 · 백업이 매장 수만큼 늘어난다
- **RLS를 건너뛰는 배치 전용 역할** — 편하지만 벽에 구멍을 내는 것이다

## 감수할 것

- M2가 무거워진다. JPA + 커넥션 풀에서 트랜잭션마다 매장 값을 넘기는 연결 고리를 직접 만들어야 한다 — 그 어려움이 딥 태스크의 소재다
- 테스트도 앱 역할로 접속해야 한다(Testcontainers 기본 계정은 슈퍼유저라 RLS가 안 걸린다)
