# 0013 · 프런트는 Angular SPA + TypeScript + Tailwind + spartan/ui

- **상태**: 채택
- **날짜**: 2026-11-08

## 맥락

M0에서 Angular로 정했다가 화면을 그리기 전이라 근거가 없어 다시 열었다(archive/DEVLOG_M0). M1에서 마감 입력 시안(휴대폰 · 데스크톱 각 3개)을 실제로 움직이게 그려 보니, 이 앱에서 매일 쓰는 화면이 가장 상호작용이 많았다([DESIGN 3절](../DESIGN.md#3-마감-입력)).

- 숫자 하나를 칠 때마다 손실 · 폐기율 · 진행이 바로 바뀐다
- 칸끼리 얽힌 규칙: 품절이면 남은 칸 잠금, 행방은 나머지가 폐기, 오류 줄은 합계에서 뺀다
- 입력 중 화면을 다시 그리면 커서를 잃는 문제를 목업에서 실제로 겪었다
- 저장 실패 때 입력값을 기기에 남겨 두기, 어제 값 채우기, 저장 전 빠뜨림 확인, 키보드 이동

브라우저가 화면 상태를 들고 있어야 하는 화면이다. 백엔드는 이미 API 분리 · 세션 쿠키 + CSRF · Caddy가 정적 파일을 내보내는 구조로 정했다([0006](0006-session-auth.md), [0012](0012-ops-reuse-playledger.md)).

## 결정

- **Angular**(2026-11 기준 22.x) + **TypeScript**, 화면 상태는 **signals**
- 스타일은 **Tailwind CSS 4**, 부품은 **spartan/ui**(shadcn 방식 — 부품 코드를 레포에 복사해 고쳐 쓴다)
- 빌드 결과(정적 파일)를 Caddy가 내보내고 `/api`만 Spring으로 — ARCHITECTURE 3절 그대로. SSR은 쓰지 않는다(로그인 뒤 화면이라 검색 노출이 필요 없다)
- 패키지 관리자 **pnpm**, 폴더 `frontend/`
- CSRF: Angular `HttpClient`의 XSRF 지원(`XSRF-TOKEN` 쿠키 → `X-XSRF-TOKEN` 헤더)을 쓴다
- 색 · 서체는 [DESIGN](../DESIGN.md) 토큰을 Tailwind 테마로 옮긴다
- 차트 라이브러리는 리포트 화면 시안을 그릴 때 정한다

## 검토한 대안

- **Thymeleaf + htmx** — 폼 제출 · 목록 · 조회 화면에는 가장 단순하다. 그러나 마감 입력은 칠 때마다 서버를 다녀오거나 계산용 JS(Alpine 등)를 따로 붙여야 하고, 응답 HTML로 바꿔 끼우는 방식이라 입력 중 커서를 잃는 문제가 그대로 생긴다(막으려면 morph 확장). 입력값을 기기에 남기기도 번거롭다. 결국 "htmx + Alpine + 직접 쓴 JS"가 섞인다
- **Svelte 5 (+ SvelteKit 정적 모드)** — 같은 화면을 가장 적은 코드로 만든다. 프런트를 가볍게 가고 백엔드에 집중할 때의 답이다. 이 레포의 목표는 프런트도 "정해진 구조"(라우팅 · 폼 검증 · HTTP 가로채기 · DI)를 탄탄하게 배우는 것이라 Angular로 갔다
- **SolidJS** — signals는 좋지만 문법이 React와 거의 같다
- **Lit(웹 컴포넌트)** — 상태 관리 · 라우팅을 직접 골라 붙여야 한다
- **Hotwire(Turbo + Stimulus)** — htmx와 같은 계열이라 같은 약점
- **Vaadin** — 사용자마다 화면 상태를 서버 메모리에 둬서 1GB 서버에 부담이고, API 분리 구조와 어긋난다
- React · Vue는 사용자가 이번 비교에서 뺐다

## 감수할 것

- 배울 게 가장 많다(TypeScript · 컴포넌트 · signals · 라우팅 · 폼 · DI). 타이핑 학습 모드에서 칠 코드도 많다
- 화면과 API가 갈라져 기능 하나를 두 곳에서 고친다 — 한 레포라 커밋은 하나. 요청 · 응답 타입을 손으로 맞출지 OpenAPI에서 생성할지는 M2에서 정한다
- 국내 채용은 React가 압도적이다 — 이 프로젝트는 취업 일정용이 아니라 받아들인다
- CI에 pnpm 린트 · 테스트 · 빌드가 더해진다
