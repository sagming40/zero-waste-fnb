# 0015 · 차트는 Apache ECharts (+ ngx-echarts)

- **상태**: 채택
- **날짜**: 2026-11-08

## 맥락

[0013](0013-frontend-angular.md)에서 차트 라이브러리는 리포트 시안 때 정하기로 미뤘다. 오늘 손실 시안(F19)을 그리며 화면마다 필요한 차트를 훑어보니 난이도가 크게 갈린다.

| 화면 | 차트 |
|---|---|
| 오늘 손실 (F19) | 요일 막대 7개 + 지난주 겹침, 가로 막대 |
| 백테스트 (F18) | 날짜별 선 여러 개(실제 · 예측 · 기준선 2개), 확대, 툴팁 — 가장 어렵다 |
| 탄소 리포트 (F20) | 월별 누적 막대, 재료별 비중 |
| 예측 · 권장 (F16 · F17) | 시안 전 |

## 결정

- **Apache ECharts**(2026-11 기준 6.x) + Angular 감싸개 **ngx-echarts**(22.x, Angular 22 지원)
- **모든 차트를 ECharts로** — 오늘 손실의 간단한 막대까지. 툴팁 · 범례 · 색 · 어두운 모드가 화면마다 같은 모양이 된다
- 무게 줄이기: `echarts/core`에 쓰는 차트 · 부품만 등록한다(BarChart · LineChart · Grid · Tooltip · Legend · DataZoom …). 차트가 있는 화면만 지연 로딩
- 렌더러는 **SVG**(데이터가 수백 점 이하라 충분하고, 글자가 선명하고 확대해도 안 깨진다). 백테스트 점이 수천 개를 넘으면 그 차트만 Canvas
- 색은 [DESIGN 2절](../DESIGN.md#2-색) 토큰에서 — 손실은 `loss`, 비교 · 지난주는 `muted`, 절약은 `accent`. CSS 변수를 읽어 ECharts 테마로 넘겨 어두운 모드를 따라가게 한다
- `prefers-reduced-motion`이면 차트 애니메이션을 끈다([0014](0014-motion-gsap.md))
- 차트만으로 숫자를 전하지 않는다 — 합계 · 비교는 글자로도 둔다(시안 그대로)

## 검토한 대안

- **Chart.js** — 가볍고 배우기 쉽다. 막대 · 선은 충분하지만 확대 · 누적 · 많은 시리즈는 플러그인을 붙여야 하고, 백테스트 비교 화면에서 손이 더 간다
- **직접 SVG(Angular 컴포넌트)** — 가장 가볍고 배울 게 많다. 오늘 손실 막대 수준은 쉽지만 백테스트(확대 · 툴팁 · 축)를 직접 만들면 차트 만들기가 일이 된다. 차트 종류마다 모양이 달라질 위험도 있다
- **D3** — 무엇이든 되지만 차트 하나하나를 손으로 짜는 도구라 이 앱에는 과하다
- **간단한 막대는 직접 SVG, 어려운 것만 ECharts** — 가볍지만 두 방식의 툴팁 · 색 · 어두운 모드를 따로 맞춰야 한다

## 감수할 것

- 번들이 커진다 — 필요한 부품만 등록 + 지연 로딩으로 줄이고, 첫 화면(마감 입력)에는 들어가지 않게 한다. 오늘 손실이 첫 화면이 되면 크기를 재서 DEVLOG에 남긴다
- ECharts 옵션 객체가 길다 — 공용 테마 · 기본 옵션을 한 곳에 두고 화면은 데이터만 넘긴다
