- 손실은 주 색과 따로 둔다 — "낭비된 돈"은 어느 화면에서든 `loss` 하나로 보인다. 오류도 `loss`를 쓴다(둘 다 "손해 · 고칠 것")

- 색만으로 뜻을 전하지 않는다 — 오류는 빨간 테두리 + 문구, 품절은 칩 + 글자

## 3. 마감 입력

시안 비교와 고른 이유는 [mockups/README](mockups/README.md#마감-입력--시안-휴대폰-a--데스크톱-a-채택-2026-11-08). 받는 값 · 저장 규칙은 [DATA_MODEL 4절](DATA_MODEL.md#4-마감--재고-규칙).

### 3.1 모양

- **부품 규칙**: 받는 데이터 모양이 같으면 같은 부품. 숫자 하나(음료 판매량) = **한 줄**, 당일 생산품(만든 · 남은 · 품절 · 행방) = **카드**. 재고 · 입고 화면도 이 규칙을 따른다
- **휴대폰**: 머리(매장 · 날짜 ‹ › · 영업 / 휴무 · 어제 값 불러오기 · 진행) → 분류 순서(음료 · 베이커리 · 샐러드 · 샌드위치 · 도시락)로 한 줄 / 카드 → **아래 고정 바**(오늘 폐기 손실 · 폐기 수 · 폐기율 · 저장)
- **데스크톱**(넓은 화면): 같은 순서를 분류별 **표**로, 카드 한 장 = 표 한 줄, 행방은 줄 아래로 펼친다. 아래 고정 바 대신 **오른쪽 요약 패널**(손실 · 폐기율 · 진행 막대 · 아직 안 친 메뉴 · 저장)이 따라온다. 분류 머리에 n/m(다 치면 ✓), 줄마다 그 메뉴의 폐기 손실, 분류 합계
- 숫자 칸은 스테퍼(− 숫자 +)이면서 직접 칠 수 있다 — 60개를 +로 60번 누를 수 없다
- 아직 안 건드린 메뉴는 휴대폰 점선 테두리, 데스크톱 줄 왼쪽 호박색 막대
- 나중에: 데스크톱 표에 "모든 칸 펼치기"(행방 칸을 줄 안에 펼친 스프레드시트 모양) — 메뉴가 많아질 때. 화면 하나에 표 부품 하나로 만들어 두면 모드만 더하면 된다

### 3.2 동작 규칙

| 규칙 | 이유 |
|---|---|
| 날짜를 머리에 두고 ‹ › 로 바꾼다 | 자정을 넘겨 마감하면 "오늘"이 다음 날이 된다. 새벽 몇 시까지를 전날로 볼지는 프런트를 만들 때 정한다 |
| 영업 / 휴무 전환, 휴무면 목록 대신 사유 하나(정기 · 임시 · 공사 · 행사 · 기타) | 휴무와 "판매 0"을 구분해야 예측에서 뺄 수 있다 |
| 품절을 켜면 남은 수량이 0으로 잠기고, 품절 시각(~12시 · ~15시 · ~18시 · 마감 직전)을 묻는다 | 품절인데 남았다는 모순을 막는다. 시각은 검열된 수요를 추정하는 근거(DATA_MODEL 4절 1) |
| 남은 수량이 있으면 행방을 보여 주고 기본은 전부 폐기. "나누기"로 할인 판매 · 직원식 · 기부만 치면 **나머지가 폐기** | 행방 합계 = 남은 수량을 사람이 맞추지 않아도 된다. 남은 수량을 줄이면 행방을 뒤(기부 → 직원식 → 할인)부터 깎는다 |
| 남은 > 만든이면 그 칸 빨간 테두리 + 문구, 위에 "고칠 곳 n개", 저장 잠금. 오류 난 줄은 손실 합계에서 뺀다 | 틀린 숫자로 손실이 부풀어 보이지 않게 |
| **오늘 폐기 손실(원가 기준)** · 폐기 수 · 폐기율(폐기 ÷ 만든)이 입력하는 대로 바뀐다. 할인 판매 · 직원식 · 기부는 손실에서 뺀다 | 손실 원화가 매일 입력하는 동기(REQUIREMENTS 1.2의 4) |
| "어제 값 불러오기"는 **아직 안 건드린 메뉴만** 채운다. 신메뉴(어제 값 없음)는 비워 둔다 | 이미 친 값을 덮어쓰지 않게 |
| 진행 "13개 중 n개 입력". 안 건드린 메뉴가 있으면 저장 전에 "n개는 0개로 저장돼요"를 묻는다 | 빠뜨린 메뉴가 판매 0으로 들어가면 예측이 내려간다 |
| 이미 저장한 날을 열면 "언제 · 누가 저장했는지"와 "다시 저장하면 이날 전체가 바뀐다"를 띠로 | 같은 날 다시 입력 = 통째로 바꿈(DATA_MODEL 4절 4). 두 기기에서 동시에 열면 나중 저장이 이긴다는 것도 이 띠로 알린다 |
| 데스크톱 키보드: `Tab` 옆 칸 · `Enter` 같은 항목의 아래 칸(`Shift + Enter` 위) · `Ctrl + S` 저장 | 마우스 없이 끝낸다 |
| 입력 중 화면을 다시 그려도 커서가 있던 칸을 잃지 않는다 | 목업에서 실제로 겪었다(mockups/README) |

### 3.3 아직 안 정한 상태

저장 중 · 네트워크 실패(입력값을 기기에 남겨 두기) · 직원 권한 화면 차이 · 메뉴 없음 화면의 문구. 프런트를 정한 뒤 그린다.

## 4. 움직임

이유는 [decisions/0014](decisions/0014-motion-gsap.md).

- **입력 화면**(마감 · 재고 · 입고): 펼침 · 들어오기 · 값이 바뀔 때 짧은 전환(200ms 안팎)까지. 칠 때마다 번쩍이지 않는다
- **연출 구역**: 소개(랜딩) · 로그인 · 리포트 맨 위 숫자(카운트업). 스크롤 연동 · 글자 효과는 여기서만
- `prefers-reduced-motion`이면 연출을 끄고 전환은 즉시

## 5. 서체

시안은 Pretendard(가변)를 쓴다. 숫자는 `tabular-nums`(자릿수가 흔들리지 않게). 확정은 프런트를 정할 때 — 파일로 함께 넣을지 CDN일지가 프런트 빌드에 달려 있다.

## 6. 문구

- **"버리다"를 쓰지 않는다** (2026-11-08 사용자 지시) — 가볍고 장난스럽게 들린다. 결과(돈 · 탄소)는 **"낭비"를 수동형으로**(2026-11-08 사용자 지시 — 사람이 아니라 돈이 주어라 탓하는 말로 들리지 않는다): 낭비된 돈 · 덜 낭비됐어요 · 무엇이 낭비됐나. 행동(남은 것을 처리함)은 **"폐기"**: 남음 → 폐기 · 폐기율 · 재료 폐기
- 남았지만 낭비되지 않은 것(할인 판매 · 직원식 · 기부)은 **"절약"**(절약 ₩2,200 · 직원식으로 절약했어요) — 2026-11-08 사용자 지시, "구하다" · "아끼다"는 쓰지 않는다
- 줄어든 것을 말할 때는 "덜 낭비됐어요"처럼 사람을 탓하지 않는 말로. 늘었을 때도 숫자와 사실만("₩6,700 더 낭비됐어요"), 꾸짖는 말을 붙이지 않는다
- 계산에서 빼는 것은 **"제외"**(손실에서 제외됨 · 합계에서 제외됐어요) — "빠짐 · 뺐어요"는 쓰지 않는다(2026-11-08 사용자 지시)
- 존댓말 해요체(“~했어요”, “~해요”). 단 **로그인 실패 · 잠김처럼 계정 보안을 알리는 문구는 합쇼체**(“올바르지 않습니다”, “제한됩니다”) — 2026-11-09 사용자 지시
- 화면에서 점주를 부를 때는 **"사장님"**(사장님께 새 링크를 받아 주세요 · 사장님에게만 보여요). 역할 이름(설정 · 직원 목록의 칸)은 "점주 · 직원" 그대로 — 2026-11-09

## 7. 오늘 손실

시안 비교 · 고른 이유는 [mockups/README](mockups/README.md#오늘-손실--시안-휴대폰-a--데스크톱-a-채택-2026-11-08). 차트는 ECharts([0015](decisions/0015-charts-echarts.md)).

### 7.1 모양

- **휴대폰**: 오늘 폐기 손실(크게) + 지난주 같은 요일 대비 + **한 줄 요약**(손실이 가장 큰 한 가지와 비중) + 메뉴 폐기 · 폐기율 · 절약 → 무엇이 낭비됐나(손실 큰 순, 재료는 "재료" 표시) → 절약 → 이번 주 막대(지난주 점선 겹침) · 합계 · 대비 · 평균 폐기율 → 오늘 마감 고치기
- **데스크톱**: 위에 숫자 넷(오늘 손실 · 오늘 폐기율 · 이번 주 손실 · 오늘 절약) → 이번 주 막대 + 분류별 → 낭비된 것 표(무엇 · 구분 · 양 · 원인 · 행방 · 손실 · 비중)
- **막대를 누르면 그날**: 휴대폰은 막대 아래에 그날 카드(닫기), 데스크톱은 분류별 · 표가 그날로 바뀐다(오늘로). 맨 위 오늘 숫자는 그대로
- 예측(M4)이 생기면 한 줄 요약 옆에 "내일 권장 n → m개"

### 7.2 규칙

| 규칙 | 이유 |
|---|---|
| 손실 = 메뉴 폐기(레시피로 펼친 원가) + 재료 폐기(로트 단가) | 재료 폐기(F09)도 낭비된 돈이다 |
| 할인 판매 · 직원식 · 기부는 손실에서 제외하고 "절약"으로 따로 | DATA_MODEL 4절 2 |
| 비교는 **지난주 같은 요일** | 베이커리는 요일마다 판매가 크게 다르다 — 예측 기준선(F18)과 같은 눈높이 |
| 줄면 `accent`, 늘면 `loss` | 줄어든 것까지 빨갛게 보이면 헷갈린다 |
| 마감을 입력하지 않은 날은 점선 막대 + "?", 합계와 지난주 비교 **양쪽에서** 그 요일을 제외 | 0으로 세면 "이번 주 덜 낭비됐다"로 속는다 |
| 휴무일은 막대 없이 "휴무", 계산에서 제외 | 판매 0과 다르다(F08) |
| 오늘 마감 전이면 숫자 대신 "마감 전" + 마감 입력 버튼, 오늘 막대는 "…" | ₩0으로 보이면 아무것도 낭비되지 않은 줄 안다 |
| 기록이 하나도 없으면 "첫 마감 입력하기" | 처음 쓰는 매장 |
| 폐기율 = 메뉴 폐기 ÷ 만든 수량(당일 생산품). 이번 주는 날마다 폐기율의 평균 | 재료에는 "만든 수량"이 없다 |
| 이번 주 = **월요일 시작** 고정 | 매장마다 휴무 요일이 달라도 뜻이 같다. PostgreSQL `date_trunc('week')`와 같다 |
| 금액은 원 단위 전부(₩22,800), 막대 위만 "2.3만" | 막대 위는 칸이 좁다 |
| 한 줄 요약은 "가장 큰 한 가지"만. 받침에 따라 이/가 | 문장 규칙을 늘리지 않는다 |

## 8. 앱 이동 · 첫 화면

화면 지도와 이동 시안은 [mockups/Map.html](mockups/Map.html), 고른 이유는 [mockups/README](mockups/README.md#앱-화면-지도--이동-시안-휴대폰-a--데스크톱-a-채택-2026-11-08).

### 8.1 흐름과 묶음

- 소개(F27, 공개) → 로그인 · 가입(F01, 직원은 초대 링크) → 첫 매장 등록(F02) 또는 매장 고르기(매장이 둘 이상일 때만) → 앱
- 앱 안의 화면은 네 묶음: **매일**(오늘 · 마감 · 내일 권장) · **재고**(재고 · 입고 · 재료 폐기 · 실사) · **리포트**(탄소 · 백테스트) · **설정**(메뉴 · 레시피 · 매장 · 직원). Angular 라우트도 이 묶음대로

### 8.2 이동

- **휴대폰: 아래 탭** — 점주 오늘 · 마감 · 재고 · 리포트 · 더보기, 직원 마감 · 입고 · 재료 폐기 · 더보기. 재고 탭 안에서 재고 · 입고 · 재료 폐기 · 실사를 위쪽 칩으로. 더보기에 내일 권장(M4 전) · 메뉴 · 레시피 · 매장 · 직원 · 매장 바꾸기 · 로그아웃
- **데스크톱: 왼쪽 메뉴** — 묶음 제목 아래 화면 목록, 위에 매장 고르기, 마감 전이면 "오늘 마감 입력" 버튼, 아래에 접기 · 사용자
  - **폭 조절**: 오른쪽 가장자리를 끌어 180 ~ 360px. 120px 아래로 끌면 접힌다. 가장자리를 두 번 누르면 기본 232px. 키보드로는 가장자리에 초점을 두고 ← →(16px씩)
  - **접기 · 펴기**: 아래 « / » 단추. 접히면 64px에 아이콘만, 마우스를 올리면 화면 이름(title)
  - 폭 · 접힘은 **그 브라우저에 기억**한다(localStorage — 서버에 저장하지 않는다. 읽기 실패면 기본값)
  - 끄는 동안 오른쪽 화면이 마우스를 가로채지 않게 막는다(목업에서 iframe으로 확인)

### 8.3 첫 화면

| 사람 | 첫 화면 | 규칙 |
|---|---|---|
| 점주 | **오늘** | 시간이 아니라 **오늘 마감했나**로 바뀐다 — 마감 전이면 맨 위에 "오늘 마감 입력", 마감 후면 오늘 손실(7절). M4부터 아침에는 "오늘 만들 것"이 맨 위. 매장마다 마감 시각이 달라 시간 규칙은 틀리기 쉽다 |
| 직원 | **마감** | 직원이 하는 일이 마감 · 입고 · 폐기뿐이다(F03) |

### 8.4 점주와 직원

- 직원 메뉴: 마감 · 입고 · 재료 폐기 + 매장 바꾸기 · 로그아웃. "오늘" · 재고 · 실사 · 리포트 · 설정은 점주만
- **직원에게 금액(원가 · 손실 ₩)을 보이지 않는다** — 원가는 가게 사정이다. 마감 입력의 아래 바 · 옆 요약은 "오늘 폐기 n개 · 폐기율", 표의 폐기 손실 칸은 "폐기 n개"
- 화면에서 숨기는 것으로 끝내지 않는다 — **API도 직원 요청에는 금액을 내려주지 않는다**(M2에서 테스트로)

## 9. 로그인 · 가입 · 초대

시안은 [mockups/Auth.html](mockups/Auth.html), 고른 이유는 [mockups/README](mockups/README.md#로그인--가입--초대--시안-휴대폰-a--데스크톱-b-채택-2026-11-09).

### 9.1 모양

- **휴대폰: 한 화면에 로그인 / 가입 탭.** 칸이 다 보여 한 번에 끝난다. 이메일을 먼저 받는 안(B)은 이메일만 넣어도 가입된 사람인지 드러나서 뺐다
- **데스크톱: 왼쪽 소개 + 오른쪽 입력.** 왼쪽은 주 색 바탕에 한 줄 · 설명 · 숫자 셋, 오른쪽 입력은 휴대폰과 같은 부품. 소개 페이지(F27)가 생기기 전에도 처음 온 사람이 무엇인지 안다
- 로그인 아래에 "데모 매장 둘러보기"(읽기 전용)

### 9.2 규칙

| 규칙 | 이유 |
|---|---|
| 가입 칸은 이름 · 이메일 · 비밀번호 셋 + 약관 동의 | 매장 정보는 다음 화면(첫 매장 등록)에서 받는다 |
| 비밀번호 8자 이상, 조합 규칙 없음 | 조합 규칙은 외우기 어려운 짧은 비밀번호만 늘린다 |
| 로그인 실패는 **어느 쪽이 틀렸는지 말하지 않는다** | 가입된 이메일인지 드러나지 않게 |
| 5회 연속 실패하면 15분 동안 로그인 제한, 남은 시간을 보인다 | 비밀번호 맞히기 막기. 구현은 M2 |
| 가입 뒤: 점주는 첫 매장 등록, 초대로 들어온 직원은 매장 등록 없이 마감 | 8.3 첫 화면 |

### 9.3 초대 링크

링크를 연 사람의 사정마다 화면이 다르다. 초대 화면은 맨 위에 **누가 · 어느 매장 · 역할 · 기한**, 그 아래 "직원은 마감 · 입고 · 재료 폐기를 입력해요 · 금액은 사장님에게만 보여요"를 먼저 보인다.

| 사정 | 화면 |
|---|---|
| 계정 없음 | 가입 칸 + "가입하고 들어가기". 계정이 있으면 "로그인하고 들어가기" |
| 이미 로그인 | 내 이름 · 이메일 + "○○ 직원으로 들어가기". 내 계정이 아니면 로그아웃하고 다른 계정으로 |
| 이미 그 매장 직원 | "이미 초대되었어요" + 매장으로 가기. 링크는 쓴 것으로 치지 않는다 |
| 만료 · 이미 사용 · 취소 | "이 초대 링크는 만료되었어요" 한 문구 + 사장님께 새 링크를 받으라는 안내 |

### 9.4 아직 안 정한 것

- **비밀번호 찾기** — M2에는 메일 발송이 없다. 시안은 "사장님이 직원 비밀번호를 다시 정해 줌"이고, 점주 자신이 잊었을 때는 비어 있다
